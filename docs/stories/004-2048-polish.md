# Story 004 — 2048 Polish Pass (Mobile Scroll, Brand Colors, Animation, Persistence)

**Status:** Ready for development
**Priority:** High (community-reported bug + CEO brand feedback)
**Target release:** v0.4.0
**Source of demand:**
- GitHub issue #12 (jerrodlv, 2026-08-05): "2048 screen scrolls in mobile — up/down swipe scrolls the whole screen a bit instead of just interacting with the game area."
- CEO feedback via Bluesky (2026-08-05): 2048's amber/grayscale palette doesn't match the brand red/gold/blue used in Minesweeper + Simon.
- Deferred from v0.3.0: merge-animation approximation (all cells ≥ 8 pulse, not just merged ones) and difficulty selection not persisting across reloads.

## Summary

Polish pass on the 2048 game. No new mechanics. Four fixes: stop page scroll on mobile swipes, bring the palette in line with the Flambeee brand, make merge animations fire only on tiles that actually merged, and remember the player's board-size choice between visits.

## Acceptance Criteria (BDD)

### Scenario 1: Swiping on mobile does not scroll the page
**Given** I am playing 2048 on a touch device
**When** I swipe up, down, left, or right over the game area
**Then** the game board moves in that direction
**And** the page does not scroll or bounce

### Scenario 2: Vertical swipe on the page background does not scroll
**Given** I am playing 2048 on a touch device
**When** I swipe vertically anywhere on the page
**Then** the page does not scroll
**And** the game responds to the swipe as a move

### Scenario 3: Tile colors match the Flambeee brand palette
**Given** the Flambeee brand palette (dark navy background, red accent `#e94560`, gold `#f5a623`, blue highlights)
**When** I open the 2048 game
**Then** the page background, header, controls, and tiles use the brand palette
**And** the game is visually consistent with Minesweeper and Simon

### Scenario 4: Only merged tiles animate
**Given** a move that merges exactly one pair of tiles
**When** the move completes
**Then** only the tile(s) that actually merged show the merge pulse animation
**And** tiles that merely slid do not pulse

### Scenario 5: Board size persists across reloads
**Given** I select the Hard 5×5 board
**When** I reload the page or return later
**Then** the board is still 5×5
**And** the selector shows "Hard 5×5"

### Scenario 6: Board size persists per browser
**Given** I select the Classic 4×4 board
**When** I reload the page
**Then** the board is still 4×4
**And** the selector shows "Classic 4×4"

### Scenario 7: Existing behavior is unchanged
**Given** the current 2048 game
**When** I play a normal game on desktop with arrow keys / WASD
**Then** slide, merge, scoring, win, and game-over behavior are unchanged
**And** the best score still persists in localStorage

### Scenario 8: Game over is detected when no moves remain
**Given** a board with no empty cells and no possible merges
**When** I attempt any move
**Then** the Game Over overlay appears with the final score
**And** the overlay offers a Play Again button

> **Found during development (Kai):** `move()` early-returns on `!movedAny` before `checkGameOver()` is reached, so the game-over overlay was unreachable in normal play. Fixed as part of this story.

## Notes for Development

- Mobile scroll fix: the page already sets `touch-action: manipulation` on body; the swipe handler is passive. Consider `touch-action: none` on the game area (or `overscroll-behavior: none` on body) so vertical swipes are captured by the game instead of the browser. Keep the page scrollable if content overflows on small screens — the fix should target the game interaction, not break layout.
- Brand palette reference: `src/minesweeper.html` and `src/simon.html` use `--bg: #1a1a2e`, `--accent: #e94560`, `--flag: #f5a623`. 2048 should adopt the same CSS variables and a tile ramp derived from the brand colors (gold family for high tiles is acceptable — it matches the brand gold).
- Merge animation: `move()` currently marks every cell with value ≥ 8 as merged when any merge happened. Track the actual merged positions in `slideLine` (it already knows which pairs merged) and mark only those.
- Persistence: store the selected size under a localStorage key (e.g. `flambeee-2048-size`) and read it on load, same pattern as the best score.
