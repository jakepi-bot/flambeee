## Summary

TRACE is the twelfth Flambeee game and its mechanic is original: the line you draw becomes the walls you walk. There is no vehicle, no momentum, no physics body, no jump. You draw one continuous stroke with a finger or mouse inside a square field, spending from a visible ink budget. When you lift, the game forges your stroke into level geometry: every grid cell your stroke touched becomes wall, loops in your line become rooms, straight runs become corridors. Then you walk that level one cell per arrow press to reach the exit before 80 moves run out. The end of the run tells you one plain sentence: what percentage of your own ink you actually brushed against. It is a mirror, not a grade. If this build can only be described as Line Rider with a character, it has failed and must be killed rather than shipped.

## Story

As a player, I draw one continuous stroke so the game forges it into walls I then walk to the exit.

## Functional requirements

FR-1 (contract 1.1, states). States and what renders in each: TITLE shows the empty field with the skeleton fragment, title copy, Start button, day label, best today, pad hidden or inert; DRAW shows field plus skeleton plus live ink plus ink meter, panel copy "Draw one line, then lift." plus Clear button, pad hidden; FORGE shows the forged walls transiently with "Forging." and accepts no input; RUN shows the forged field with player glyph, exit glyph, moves left and coverage so far, 4-dir pad visible; WIN shows the final field with the walked path, "EXIT REACHED" plus one feedback sentence plus Walk again plus New line; LOSE shows the final field with the walked path, "OUT OF MOVES" plus one feedback sentence plus Walk again plus New line.

FR-2 (contract 1.1, transitions). TITLE to DRAW on Start click or Enter or Space with state TITLE; ink cleared, cursor reset; this is the run-start entry (Story 170 hook). DRAW to FORGE on pointer lift, pointer-capture loss with a non-empty stroke, or keyboard Enter; there is no Forge button, lift or Enter forges, Clear clears; validation runs first and a stroke under MIN_STROKE_PX or under MIN_CELLS distinct player wall cells is refused with state staying DRAW, stroke kept, short-line message shown. FORGE to RUN always and synchronously; FORGE never fails and never branches; pos set to start, moves used 0, visited set holds start. RUN to WIN when pos equals exit after a move; RUN to LOSE when moves used reaches MOVE_LIMIT without reaching exit. WIN or LOSE to RUN on Walk again: same forged field, pos reset to start, moves 0, visited cleared, never counts. WIN or LOSE to DRAW on New line: keeps the day skeleton, clears ink, never counts. WIN or LOSE to TITLE on Back link only; the next Start counts as a new play. DRAW to DRAW on Clear (Esc key or Clear button): stroke emptied, meter reset, message cleared.

FR-3 (contract 1.1, input map). Pointer drag on the field paints ink in DRAW (primary path) and does nothing elsewhere; arrows or WASD paint-cursor steps in DRAW (parity path, 1 cell per press) and move 1 cell per press in RUN; Enter or Space finishes to FORGE in DRAW, walks again on WIN/LOSE end screens, starts on TITLE; Esc clears the stroke in DRAW and does nothing elsewhere; the on-screen pad is hidden except in RUN where it moves 4-dir; a wall bump in RUN is silent (pos unchanged, moves unchanged, no message).

FR-4 (contract 1.1, DRAW pointer discipline). The drawing surface sets `touch-action: none`, takes pointer capture on pointerdown, tracks exactly one pointerId and ignores all other concurrent pointers, converts to internal space per 1.6, clamps to 0..324, and calls preventDefault on the move path so a drag never scrolls the page. Points falling outside the field clamp to the edge, never dropped, so fast fingers punch no holes in the ink.

FR-5 (contract 1.1, DRAW keyboard discipline). A paint cursor starts on the first skeleton cell. Each arrow or WASD press moves the cursor one cell orthogonally, clamped to the interior 1..7, and paints the entered cell, adding CELL_PX 36 px to ink length. Diagonal input does not exist. Backspace is not required. Esc clears. Enter finishes to FORGE through the same minimum gate. A step into an already-wall cell still moves the cursor but changes nothing in the painted set and adds 0 px, so ink length and wall count cannot diverge.

FR-6 (contract 1.2, forge rule). Constants GRID 9, FIELD_INTERNAL_PX 324, CELL_PX 36, RESAMPLE_STEP_PX 2. All forge math happens in internal space; the rendered box never enters the forge. Step 1 resample: walk the raw pointer point list P in internal px and emit interpolated points every 2 px of arc length by linear interpolation, always including the first and last raw points; pure function of P, no timestamps, no velocity, no smoothing, no simplification (keyboard path skips to step 2 with its painted cell list). Step 2 quantize: col equals floor(x / 36), row equals floor(y / 36), each clamped to 0..8; a point exactly on a cell boundary belongs to the higher-index cell; a point exactly on the outer max edge (324) clamps to index 8. Step 3 walls: PLAYER_WALLS is the distinct set of quantized player cells; WALLS equals BORDER union SKELETON union PLAYER_WALLS. Step 4 carve: START and EXIT are removed from WALLS unconditionally; ink over them never seals them. Step 5 stitch: BFS on floor cells (non-wall, 4-connected) from START; if EXIT is unreached, carve an L corridor (cells from START along its row to the EXIT column, then along that column to EXIT) out of WALLS, re-run BFS; FORGE therefore always emits a field where EXIT is reachable and FORGE to RUN is unconditional. Step 6 RUN bookkeeping: visited holds START; brushed is the count of PLAYER_WALLS cells orthogonally adjacent to any visited cell, updated on each move. Determinism means exactly: the forge is a pure total function of the point list (same points forge byte-identical walls, resampling erases event-timing differences, floor plus clamp maps every point to exactly one cell); skeleton, START and EXIT are pure functions of the UTC day index D. Cross-player stroke equality is NOT claimed: two human strokes that merely look alike may quantize differently near a cell edge.

FR-7 (contract 1.2, formulas and copy). inkLenPx is resampled polyline arc length in 2 px steps; inkCells equals count of PLAYER_WALLS with gate at least 3; wallCount equals count of WALLS after carve and stitch; brushed equals PLAYER_WALLS cells 4-adjacent to any visited cell; pct equals round(100 times brushed divided by inkCells); movesLeft equals 80 minus movesUsed. Exact copy: WIN title "EXIT REACHED" with end line "You brushed {pct}% of your line."; LOSE title "OUT OF MOVES" with the same end-line shape; DRAW short refusal "That line is too short to walk. Draw a longer line." with no state change; ink exhausted mid-stroke "Ink full. Lift to walk." with further points ignored until lift; HUD shows "Best today: {n}%" beside the plays line.

FR-8 (contract 1.3, tuning). All constants live in CONFIG in `website/games/trace.html`: GRID 9 (locked), FIELD_INTERNAL_PX 324 (locked), FIELD_MIN_RENDER_PX 240 (240..324), CELL_PX 36 (locked), RESAMPLE_STEP_PX 2 (1..4), MIN_STROKE_PX 108 (72..180), MIN_CELLS 3 (2..5), INK_BUDGET_PX 1200 (800..2000), MOVE_LIMIT 80 (40..120), MANHATTAN_MIN 8 (6..10), COUNT_KEY flambeee-trace-plays, BEST_KEY flambeee-trace-best, COUNT_CAP 9007199254740991 (fixed). GRID, FIELD_INTERNAL_PX and CELL_PX are locked together (324 / 9 = 36); Riven may not change one without the other two. Render scale is derived, not a CONFIG value.

FR-9 (contract 1.4, edge cases). Single tap dot refused by both gates, DRAW stays, short-line message. Fast finger leaving the field clamps to the edge, stroke continues, no holes. Second finger during DRAW ignored. Ink budget hit mid-stroke ignores extra points, shows the ink-full message, lift forges. Ink over START or EXIT carved to floor silently. Ink walling off EXIT gets the silent L stitch corridor, always reachable. Ink covering the whole interior still yields a path via carve plus stitch. Keyboard cursor at the interior edge clamps to 1..7, paints nothing new, no error. Enter or Space auto-repeat is state-guarded: FORGE and RUN entries act once per state, repeat in RUN finds no binding beyond one move per keydown event. Resize or rotate mid-draw touches nothing: stored points are already field-relative internal px and the rendered box rescales per 1.6 without touching the stroke. Blocked or corrupt storage falls back to memory silently for best and plays.

FR-10 (contract 1.6, responsive field). INTERNAL space is exactly 324 by 324 with CELL_PX 36, forever. RENDERED box scale equals min(1, contentBoxPx / 324) where contentBoxPx is the field container width (viewport width minus 24 px body padding); display size is 324 times scale square, never larger than 324, never below FIELD_MIN_RENDER_PX 240 (at 320 px wide it renders at 296 px). Pointer conversion: fieldX equals (clientX minus rect.left) divided by scale, fieldY equals (clientY minus rect.top) divided by scale, then clamp each to 0..324. At 320, 375, 390 and 1280 px widths, document.scrollWidth stays at most window.innerWidth and the field is fully visible at scrollY 0.

## Acceptance criteria (BDD, observable in product)

Design-owned observable criteria are in contract subsection 1.5; AC-1 through AC-12 map them directly. AC-13 through AC-24 pin the remaining normative behaviors above.

1. Given TITLE, when the player presses Start, then state is DRAW and the ink meter reads 0 of 1200 px. (design 1.5.1)
2. Given DRAW with a 40 px stroke, when the player lifts, then state stays DRAW and the message reads "That line is too short to walk. Draw a longer line.". (design 1.5.2)
3. Given DRAW with a 200 px loop stroke, when the player lifts, then FORGE renders and RUN begins with the player glyph on the start cell. (design 1.5.3)
4. Given RUN, when the player presses one arrow against a wall, then position is unchanged, moves used is unchanged, and no message appears. (design 1.5.4)
5. Given RUN on a straight 5-cell ink line level, when the player walks it, then each press moves exactly one cell with no slide, glide, or carry. A track racer cannot satisfy this scenario: there is no speed, no momentum, no vehicle glyph, no gravity, one press moves at most one cell, wall contact costs nothing, and standing still is always legal. (design 1.5.5; anti-Line-Rider clause)
6. Given RUN with a self-crossing stroke, when the forged field renders, then at least one pocket floor cell exists (a floor cell with 3 or more of 4 neighbors wall), which straight ink never produces. (design 1.5.6)
7. Given RUN at the exit cell, when the player enters it, then state is WIN, the title reads "EXIT REACHED", and the end line reads "You brushed {pct}% of your line." with pct equal to round(100 times brushed divided by inkCells). (design 1.5.7)
8. Given RUN with 80 moves used and pos not on exit, when the 80th move lands, then state is LOSE with the title "OUT OF MOVES" and the same sentence shape. (design 1.5.8)
9. Given WIN or LOSE, when the player picks Walk again, then the same field reappears with moves reset and the plays line unchanged. (design 1.5.9)
10. Given any DRAW drag on a 375 px wide viewport, when the finger moves, then the page does not scroll (window.scrollY stays 0). (design 1.5.10)
11. Given viewport 320x568, when the page loads and DRAW begins, then document.scrollWidth is at most window.innerWidth and the whole field is visible at scrollY 0. (design 1.5.11)
12. Given the same relative stroke drawn at rendered widths 320 px and 1280 px, when both forge, then the wall sets are identical cell for cell. (design 1.5.12)
13. Given WIN or LOSE, when the player picks New line, then DRAW begins with the day skeleton kept and the ink cleared, and the plays line is unchanged.
14. Given WIN or LOSE, when the player follows the Back link and presses Start again, then a new run begins and the plays line increments by exactly 1.
15. Given DRAW with ink on the canvas, when the player presses Esc or the Clear button, then the stroke is emptied, the meter resets, and the message clears, with state staying DRAW.
16. Given DRAW with the keyboard path, when the player presses arrows, then the paint cursor starts on the first skeleton cell, each press moves one cell orthogonally clamped to the interior 1..7 with no diagonal, and Enter forges through the same minimum gate.
17. Given DRAW with ink length at the 1200 px budget, when further points arrive, then they are ignored, the message reads "Ink full. Lift to walk.", and lift forges.
18. Given a stroke covering START or EXIT, when it forges, then both cells render as floor with no message and the level is walkable.
19. Given a stroke that walls off EXIT, when it forges, then BFS still reaches EXIT within the move budget via the silent L stitch corridor.
20. Given a second finger touching during DRAW, when it moves, then it is ignored and the single tracked stroke continues unchanged.
21. Given blocked storage, when the player starts and finishes runs, then best and plays fall back to memory silently with no error and no console error.
22. Given TITLE, Enter or Space, when pressed, then a new run begins in DRAW; given RUN, when Enter auto-repeats, then each keydown event moves at most one cell.
23. Given any viewport in 320, 375, 390 and 1280 px widths, when the page loads, then document.scrollWidth is at most window.innerWidth.
24. Given `git diff main --stat` for this story plus its same-PR riders, when the changed files are listed, then `website/games/trace.html` is the only game file changed and no other `website/` game file changed.

## Out of scope (NOT DOING)

No score, no leaderboard, no accounts. No vehicle, no momentum, no physics body, no jump: one press moves at most one cell everywhere. No letterform recognition: no glyph or character recognition, no clipping strokes into letters or kanji, no renaming the player; the forge inspects only which cells the stroke touches. No share image (a later session may export the forged grid only, never raw pointer points). No network after load: no fetch, no shared online level. No second file, no change to any other game file, no GAME_ORDER or modal or rotation change (that is Story 168), no proof harness (that is Story 169), no play-counter HUD line beyond the hook the entry point exposes (that is Story 170).
