# v0.7.0 Test Plan — Mobile Touch Quality Pass

**Version under test:** v0.7.0 (candidate)
**Author:** Scout (QA)
**Date:** 2026-08-14
**Stories:** 008 (mobile touch quality), 009 (Wordfire color legend)
**Inputs:** CEO directive 2026-08-11 (mobile touch focus), issue #26 (Wordfire iOS zoom/scroll)

## Scope

All four games (Minesweeper, Simon, 2048, Wordfire) + game hub (index.html), focused on touch ergonomics and browser-gesture interference. 2048 already had the baseline (v0.4.0) — this pass verifies no regression and standardizes the pattern.

## Test Environment

- **Automated:** Node.js DOM-stub checks (jsdom-free, hand-rolled) for static invariants (viewport meta, touch-action rules, key sizes).
- **Manual (documented, for real devices):** iPhone Safari (primary, per issue #26), Android Chrome, desktop Chrome/Firefox for regression.

---

## A. Automated static checks (node, DOM-stub)

### A1. Viewport meta present on all game pages
- Every game page declares `user-scalable=no` in the viewport meta (2048, Minesweeper, Simon, Wordfire).
- Hub (index.html) intentionally keeps zoom enabled (accessibility, Story 008 Scenario 8).

### A2. `touch-action: manipulation` on body
- body (or `*` equivalent) declares `touch-action: manipulation` on all four game pages + hub.
- Result: no double-tap zoom on rapid repeated taps (APPLE double-P case), no 300ms tap delay.

### A3. Interactive controls exempt from zoom
- Wordfire `.key`, Simon `.pad` declare `touch-action: manipulation` (or inherit body rule).
- Minesweeper `.cell` inherits body `touch-action: manipulation`; board keeps `touch-action: none` (swipe/scroll isolation).
- 2048 unchanged from v0.4.0 baseline (`manipulation` on body, `none` on board).

### A4. Wordfire keyboard tap targets (≤420px viewport)
- Letter keys: min-width ≥ 32px, height ≥ 42px (media query).
- Enter/Backspace: min-width ≥ 52px, height ≥ 42px.
- Desktop (default): min-width 34px, height 44px; wide keys 56px.

### A5. Minesweeper responsive board fit
- Cell size computed = min(configured, floor((min(innerWidth-36, 520) - 12) / cols)), floor 20px.
- At 375px viewport: Easy 9 cols → ~37px cells; Medium 16 cols → ~20px; Hard 30 cols → ~20px.
- Board must not overflow viewport horizontally at any difficulty.

## B. Manual test cases (real device)

### B1. Wordfire — rapid repeated taps (issue #26 regression test)
1. Open Wordfire on iPhone Safari.
2. Type a guess containing a double letter (e.g. APPLE → tap P twice quickly).
3. **Expected:** no browser zoom, both P's register, second P appears in the row.
4. Tap keyboard keys repeatedly across the rows; page must not scroll/jump.

### B2. Wordfire — legend (Story 009)
1. Open Wordfire (daily or practice).
2. **Expected:** legend visible between board and keyboard: green "In word, right spot", yellow "In word, wrong spot", gray "Not in word".
3. Submit a guess; legend swatches match tile colors exactly (eyeball hex-equivalent).
4. Enable colorblind mode; **Expected:** legend swatches show ● ◇ ✕ shapes matching tiles.
5. On a ≤420px phone: board + legend + keyboard all visible without unexpected scrolling.

### B3. Minesweeper — touch flagging
1. Quick tap unrevealed cell → reveals (or first-click safe logic runs).
2. Long-press (~400ms) unrevealed cell → flags it, vibrate on capable devices; no reveal.
3. Long-press a flagged cell → unflags.
4. Flag Mode toggle still works as alternate path.
5. On Medium/Hard at 375px width: board fits, no horizontal scroll; cells still tappable (20px floor is small but functional; note: on real devices verify no accidental neighbor taps dominate).

### B4. Minesweeper — scroll interference
1. Scroll the page by starting the gesture over the board (outside cells) — board has `touch-action: none`.
2. **Expected:** swiping on the board does not scroll the page (board is a game surface); page scrolls normally over header/footer.

### B5. Simon — rapid taps
1. Start game; wait for sequence; tap pads quickly in the correct order on Hard difficulty.
2. **Expected:** every tap registers; no zoom; no missed inputs.
3. Double-tap a pad twice fast — registers two inputs, no zoom.

### B6. 2048 — swipe regression
1. Swipe on the board in all 4 directions — tiles move correctly.
2. Start a swipe on the board and drag off-page — no page scroll/navigation (overscroll-behavior none + touch-action none).
3. Tap without moving — nothing happens (threshold 20px respected).

### B7. Hub (index.html)
1. Tap game cards rapidly — no zoom, cards open on first tap.
2. Page still pinch-zooms (accessibility preserved).

### B8. Cross-browser sanity (desktop)
1. Minesweeper mouse: left-click reveal, right-click flag, flag mode, first-click safe.
2. Simon keyboard QWAS still works.
3. Wordfire physical keyboard still works (type, enter, backspace).

## C. Edge cases

1. **Wordfire** — backspace key rapid taps: no zoom, deletes one letter per tap.
2. **Wordfire** — Enter rapid taps with a full valid row: only one submit per tap; no double-submit race.
3. **Minesweeper** — long-press then drag away: `touchcancel` clears the press timer, no ghost flag.
4. **Minesweeper** — resize from desktop to phone width: board re-fits on next render (new game), no overflow.
5. **Simon** — pads disabled during sequence: taps during playback ignored, no zoom.
6. **Hub** — stats lines render on mobile, cards one column, no horizontal overflow.

## Known limitations

- Automated checks are static/invariant-based; real-device feel (tap accuracy, accidental taps) needs a human hand. This plan documents the manual pass for anyone with a phone.
- 20px cells on Medium/Hard at 375px are the floor; acceptable trade-off vs horizontal scrolling. Revisit if community reports mis-taps.
